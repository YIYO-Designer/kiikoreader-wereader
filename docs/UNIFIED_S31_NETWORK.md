# S31 Wi-Fi / 无名 4G 统一源码

## 构建与范围

仓库根目录的 `metalio47` 目标维护一份 S31 源码，生成一份同时适用于现有 Wi-Fi S31 和无名 4G 配置的固件。芯片、显示后端、16 MiB 分区布局及设置命名空间保持一致。Pico 仍是独立芯片构建目标，不与 S31 共用二进制，也不链接蜂窝驱动。

按 [S31 构建指南](BUILD_METALIO_S31.md) 从根目录构建，不再执行旧 overlay 还原。全闪存包仍按 [原打包流程](FULL_FLASH_16MB.md) 生成。`variants/wuming-4g/` 保留原始来源及校验值，用于追溯，不参与设备源码视图。

## 能力、开关与连接状态

- `cellular_capability()`：本次启动的 UNKNOWN / PRESENT / NOT_DETECTED。
- `cellular_available()`：是否已取得模组有效 AT 响应。SIM、注册、用户开关不会改变已确认的硬件能力。
- `app_network_cellular_enabled()`：硬件已确认且用户开启蜂窝功能。
- `app_network_ready()`：Wi-Fi STA 或蜂窝链路已就绪；本机文件传输 AP 不作为互联网连接。

来源没有可直接读取的可信硬件 SKU 标识，所以当前使用现有模组的带帧校验 AT 传输进行探测，不以 GPIO 电平、SIM 是否存在或拨号是否成功识别机型。

## 启动探测与生命周期

S31 初始化设置后启动后台任务，延后 1.5 秒开始 AT-only 探测。探测使用 UART2（TX58/RX59/MRDY60/SRDY3），尝试当前默认速率及恢复速率，不执行 SIM 切换、注册、NAT 配置、模组复位或网络初始化。探测预算 12 秒，随后协作停止并汇合传输任务，再释放 DMA、队列、GPIO 和中断；资源汇合时间不计入探测预算，不能硬删仍在使用资源的线程。

检测期间默认呈现 Wi-Fi 界面，不阻塞开机 UI。确认存在后发布蜂窝能力并进入策略循环；未检出或资源不足则释放实例、退出后台任务，本次启动不反复拨号。负结果不写 NVS，下一次启动重新探测。模组故障、开机响应过慢或内存不足仍可能导致本次未检出，需要重启重试；两种实机的探测成功率与引脚兼容性必须验收，软件测试不能代替。

4G 开关关闭时也做硬件探测，以保证下次仍能显示开关。用户设置保持原 `cell_en`、`sim_sel`；Wi-Fi 设备忽略这两个字段，即使恢复了带 4G 开关的旧备份，也不会进入蜂窝等待。

## 网络策略与界面

Wi-Fi STA 在线优先，停止蜂窝链路；否则在硬件存在且开关开启时拨号。探测结束后保留 8 秒 Wi-Fi 宽限；初次拨号不再被错误施加 60 秒失败节流。失败拨号仍按 60 秒间隔重试。扫描 Wi-Fi 时通知策略暂停蜂窝；恢复后允许重拨。关闭、切卡、扫描请求若在拨号中到达，拨号返回后先处理请求。

连接设置由同一套项目映射驱动绘制、点击和滚动尺寸：Wi-Fi / 蓝牙 / 时间，或 Wi-Fi / 4G / SIM / 蓝牙 / 时间。能力变化后在非拖动时更新快照、复位滚动并重绘，避免隐藏项目后点击错位。4G 状态栏同时检查硬件能力和开关，无蜂窝时不留图标占位。

微信读书及在线字体等业务通过 `network_state` 获取在线状态与提示。Wi-Fi 机的离线和失败提示只提 Wi-Fi；4G 机根据开关及实际链路给出相应提示。获取 IP 不代表互联网或服务端一定可达。

云同步已在线时复用现有链路；未联网仍可进入 Wi-Fi 配网。校时组件接受应用注入的外部链路状态，不依赖主应用实现，并保留原有校时/配网互斥与取消机制。

## 验证

`tools/unified_network_host_test.py` 编译真实网络状态实现、设置项目映射及带模拟硬件/调度器的真实策略代码，检查能力/开关/链路/AP 组合、Wi-Fi 设备退出策略、无卡/拨号失败仍保留能力、Wi-Fi 优先、任务创建失败重试。

GitHub Actions 的 `unified-network-tests` 独立运行这些检查和相关板型、字体、校时回归。完整固件构建、检查结果及未验收事项应随具体提交记录；历史 v3.0.0 发行附件不是此次统一固件的测试产物。

设备验收至少覆盖：Wi-Fi 冷启动与重启；4G 正常/无 SIM/无信号/开关关闭；Wi-Fi 扫描与恢复、网络切换；设置行点击；登录/缓存/同步/在线字体；睡眠唤醒与待机功耗。本次代码合并不等于已经完成这些实机验收。
